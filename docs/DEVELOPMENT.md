# Developer Guide

## Local container workflow

```bash
cp .env.development .env
docker compose -f docker-compose.dev.yml up
```

The backend source is mounted into the backend container for Uvicorn reload. The frontend source is mounted into Vite for hot module reload.

## Quality checks

```bash
cd backend
pip install -r requirements-dev.txt
ruff check app tests
black --check app tests
isort --check-only app tests
mypy app
pytest -q

cd ../frontend
npm ci
npm run lint
npm run test
npm run build
```

## Schema changes

Create a revision after changing SQLAlchemy models:

```bash
cd backend
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

The initial revision establishes the existing schema. Review all autogenerated migrations before merging; migration execution is part of the production Compose dependency graph.

## Debugging

- API documentation: `http://localhost:8000/docs` in development.
- Logs: `docker compose logs -f backend`.
- Readiness: `curl http://localhost:8000/ready`.
- Reset development volumes only when data is disposable: `docker compose -f docker-compose.dev.yml down -v`.

## Contribution rules

Keep secrets out of commits, add tests with behavioral changes, use environment-based configuration, and run the quality checks before opening a pull request. GitHub Actions repeats those checks plus dependency auditing and container validation.
